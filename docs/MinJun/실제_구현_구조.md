# 사진 인식 앱 2107 · 실제 구현 구조

## 버전 관계

`MP1 (이미지 입력·권한) → MP2 (온디바이스 한국어 OCR) → MP3 (텍스트 이력·공유·프라이버시)` 순으로 같은 Flutter Android 앱을 확장했다. `docs/MinJun/2107_MP1`, `2107_MP2`, `2107_MP3`는 각 단계 종료 시점의 독립 실행 가능한 소스 스냅샷과 제출 ZIP이다. 최신 실행 소스는 저장소의 `screen_guide_test/`에 있다.

## 실제 코드 경로

1. **MP1**: `lib/main.dart`의 홈에서 `image_picker`로 시스템 카메라/사진 선택기를 연다. 반환된 단일 파일의 존재·크기를 확인하고 미리보기 → 이미지 표시로 이동한다. 취소, 권한 거부, 읽기·표시 실패는 화면 안내로 처리한다.
2. **MP2**: 이미지 표시 화면의 분석 버튼 → Flutter `MethodChannel('screen_guide/analyze')`의 `analyzeOcr` → Android `MainActivity.kt` → `Analyzer.kt`의 ML Kit Korean Text Recognition → 줄 목록·`recognized`/`no_text`·`processingMs` → Flutter 결과 화면. 처리 시간은 `SystemClock.elapsedRealtime()`로 측정한다. 이 경로는 네트워크 호출이나 개체 추출 모델 다운로드를 하지 않는다.
3. **MP3**: 분석 성공 콜백 → `HistoryStore.kt`의 Android `SharedPreferences`에 UUID·시각·결과 텍스트만 동기 저장 → `MethodChannel('screen_guide/history')`의 목록·삭제 → Flutter 이력 화면. 공유 버튼은 Kotlin `Intent.ACTION_SEND`/`text/plain` 시스템 공유 시트를 연다. `releaseImage`는 앱 캐시 내부 파일만 삭제하고, `purgeCachedImages`는 다음 실행 시 남은 앱 캐시 이미지를 정리한다. Android 자동 백업은 비활성화했다.

## 파일별 역할

- `screen_guide_test/lib/main.dart`: MP1~MP3의 사용자 화면과 입력·분석·이력 상태 전환.
- `screen_guide_test/android/app/src/main/kotlin/com/example/screen_guide_test/MainActivity.kt`: Flutter와 Kotlin 분석·이력·설정 API 연결.
- 같은 경로의 `Analyzer.kt`: 한국어 ML Kit OCR. 기존 전체 화면 가이드용 `analyze` 코드는 별도 보존하고 MP2·MP3의 `analyzeOcr`에서 호출하지 않는다.
- 같은 경로의 `HistoryStore.kt`: MP3 텍스트 이력 영속 저장·목록·삭제.
- `screen_guide_test/PRIVACY.md`: 저장·비저장 범위와 임시 이미지 수명.

## 확인한 실행 결과

- MP1: 카메라 권한 요청/거부 안내, 갤러리 이미지 표시, 에뮬레이터 가상 카메라 촬영 표시. MP1 제출 폴더의 스크린샷 참조.
- MP2: 같은 이미지 6줄 인식, 일반 상태 989ms·비행기 모드 1077ms; 빈 흰색 PNG 0줄 안내 70ms. `2107_MP2/제출물/screenshots` 참조.
- MP3: 33줄 인식 후 텍스트 이력 생성, 강제 종료·재시작 후 유지, 공유 시트 텍스트 미리보기, 삭제 후 빈 목록. 앱 캐시 내 이미지 파일 정리 확인. `2107_MP3/제출물/screenshots` 참조.

측정값은 에뮬레이터의 단일 실행값이다. 실제 휴대전화의 카메라 촬영 품질은 별도 검증 대상이다.
