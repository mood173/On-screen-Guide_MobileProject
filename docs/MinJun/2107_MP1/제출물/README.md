# 화면길잡이 · 사진 인식 앱 2107 MP1 (카메라와 권한)

Flutter로 만든 Android 이미지 입력 앱입니다. 카메라 촬영과 갤러리 선택 두 경로로 이미지 한 장을 가져와 미리보기와 표시 화면에 보여 줍니다. 이 입력 경로 위에 MP2의 분석이 올라갑니다.

## 실행 절차

1. Flutter와 Android SDK가 설치된 환경에서 Android 기기 또는 에뮬레이터를 연결합니다.
2. `app/` 폴더에서 `flutter pub get`을 실행합니다.
3. 같은 폴더에서 `flutter run`으로 앱을 실행합니다.
4. 홈에서 **카메라로 촬영** 또는 **갤러리에서 선택**을 누릅니다.
5. 미리보기에서 **선택한 이미지 사용**을 누르면 이미지 표시 화면이 나옵니다.

## 권한 처리 흐름

| 경로 | 필요한 권한 | 흐름 |
|---|---|---|
| 카메라 | `CAMERA` (AndroidManifest에 선언) | 버튼을 누르면 시스템 권한 대화상자가 뜹니다. 허용하면 기기 카메라 앱이 열리고, 촬영한 사진이 미리보기로 돌아옵니다. |
| 갤러리 | 없음 | Android 시스템 사진 선택기를 씁니다. 사용자가 고른 한 장만 앱에 전달되므로 전체 사진·저장소 권한을 요청하지 않습니다. |

카메라 권한을 거부했을 때:

1. `image_picker`가 `camera_access_denied` 오류를 돌려줍니다(`lib/main.dart`의 `_handlePickerError`).
2. 앱은 종료하지 않고 "권한이 허용되지 않았어요" 안내 화면으로 갑니다. 화면에는 카메라 권한이 왜 필요한지와 대신 할 수 있는 일을 적었습니다.
3. 안내 화면의 선택지는 세 가지입니다.
   - **앱 권한 설정 열기**: 이 앱의 시스템 설정 화면을 엽니다(`MainActivity.kt`의 `openAppSettings`). "다시 묻지 않음" 상태에서도 사용자가 직접 허용할 수 있습니다.
   - **갤러리에서 선택**: 권한 없이 쓸 수 있는 경로로 바꿉니다.
   - **처음으로**: 홈으로 돌아가 다시 시도합니다.

## 예외 처리

| 상황 | 처리 |
|---|---|
| 카메라·사진 선택기에서 취소(아무것도 고르지 않음) | 결과가 `null`이면 아무 일도 하지 않고 원래 화면에 머뭅니다. |
| 카메라 권한 거부 | 위의 안내 화면을 보여 줍니다. |
| 파일이 없거나 0바이트 | 오류 안내 문구를 보여 주고 다시 고를 수 있게 합니다. |
| 이미지 디코딩 실패(손상된 파일) | 이미지 자리에 안내를 표시합니다(`Image.file`의 `errorBuilder`). |
| 설정 화면을 열지 못함 | 오류를 잡아 안내 문구만 보여 줍니다. |

이미지는 서버로 보내지 않습니다. 선택기에는 위치 같은 추가 메타데이터를 요청하지 않습니다(`requestFullMetadata: false`). 사용자의 갤러리 원본은 건드리지 않습니다.

## 실행 확인

2026-11-10 Android 에뮬레이터(`Resizable_Experimental`)에서 직접 실행했습니다.

- 카메라 권한 요청 대화상자 → 거부 → 안내 화면 (`screenshots/01`, `02`)
- 거부한 뒤 갤러리에서 선택 → 이미지 표시 (`screenshots/03`)
- 권한 허용 → 가상 카메라 촬영 → 이미지 표시 (`screenshots/04`)

에뮬레이터의 가상 카메라로 확인한 것이라 실제 휴대전화의 촬영 화질은 따로 확인하지 않았습니다. 손상된 이미지 처리는 코드로 넣었고 실행으로는 확인하지 않았습니다.

`lib/legacy_analysis.dart`는 이 과제 전에 만든 글자 인식 시험 코드이며 1단계 화면에서는 호출하지 않습니다.
