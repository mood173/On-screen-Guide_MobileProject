# AI 사용 기록 · MP1

사용한 도구: Codex(코딩 에이전트). 아래 요청은 실제로 보낸 내용을 요지로 줄여 적었습니다.

## 1. 주요 프롬프트

| 번호 | 요청 요지 | AI의 답 요지 |
|---|---|---|
| 1 | 화면길잡이 프로젝트의 중간보고서와 설계 자료를 읽고, 사진 인식 앱 2107 미니프로젝트 1단계를 기존 프로젝트에서 만들 수 있는지 확인하고 제작해 달라. | Flutter·Kotlin 프로젝트에서 만들 수 있다. 1단계 기준은 카메라·갤러리 입력, 화면 표시, 권한 거부 안내, README 설명이다. 기존 글자 인식 시험 코드는 다음 단계에 쓰도록 남겨 두겠다. |
| 2 | 카메라 또는 갤러리에서 이미지 한 장을 가져와 화면에 표시하고, 권한 요청·거부·재시도 흐름을 처리해 달라. | `image_picker`로 두 경로를 만들고, 거부 오류 코드를 받아 안내 화면으로 보내는 구조를 제안. |
| 3 | 작업 환경이 컴퓨터인데 카메라 촬영을 확인할 수 있나. | Android 에뮬레이터의 가상 카메라로 흐름은 확인할 수 있다. 실제 휴대전화의 화질 확인은 별개다. |

## 2. 채택한 것

- 카메라는 기기 카메라 앱을 여는 방식(`image_picker`). 앱 안에 카메라 화면을 직접 만드는 것보다 권한·예외 경우가 적다.
- 갤러리는 시스템 사진 선택기. 사용자가 고른 한 장만 받으므로 저장소 권한을 요청하지 않아도 된다.
- 권한 거부 시 안내 화면에 "앱 권한 설정 열기"와 "갤러리에서 선택" 두 길을 함께 둔다.
- 기존 자동 분석 화면 코드는 지우지 않고 `lib/legacy_analysis.dart`로 옮겨 보존.

## 3. 고친 것과 판단

| 대상 | 바꾼 내용 | 이유 |
|---|---|---|
| 앱을 켜면 샘플 이미지를 바로 분석하던 기존 시험 화면 | 1단계 화면을 이미지 입력 전용으로 교체 | 1단계 평가는 입력과 권한 흐름이라 분석이 섞이면 확인이 흐려진다. |
| 사진 선택기 설정 | 위치 같은 추가 메타데이터를 요청하지 않음(`requestFullMetadata: false`) | 이미지 표시에는 필요 없는 정보다. |
| 검증 결과를 적는 방식 | 실행으로 본 것과 코드만 넣은 것을 나눠 적음 | 손상 이미지 처리는 코드만 있고 실행으로 보지 않았다. README에도 그렇게 적었다. |

## 4. 검증

- `dart analyze`: 문제 없음. `flutter test`: 통과. 디버그 APK 빌드: 통과.
- 에뮬레이터에서 권한 요청 → 거부 안내 → 갤러리 선택·표시 → 가상 카메라 촬영·표시를 직접 확인하고 화면을 `screenshots/`에 넣었다.
