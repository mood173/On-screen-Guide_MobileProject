# AI 사용 기록 · MP2

사용한 도구: Codex(코딩 에이전트). 아래 요청은 실제로 보낸 내용을 요지로 줄여 적었습니다.

## 1. 주요 프롬프트

| 번호 | 요청 요지 | AI의 답 요지 |
|---|---|---|
| 1 | MP1 앱에 ML Kit 또는 TFLite 분석을 붙이고 결과를 화면에 보여 달라. | 프로젝트에 이미 있는 Kotlin ML Kit 한국어 Text Recognition을 쓰자. Flutter에서 부를 `analyzeOcr` 진입점을 따로 만들고 결과 화면에 줄 목록과 처리 시간을 띄우겠다. |
| 2 | 글자를 못 찾는 이미지에서는 안내가 나오게 해 달라. | 인식 줄이 0개일 때의 처리를 추가. |
| 3 | 비행기 모드에서 동작하는지 확인하고 처리 시간을 README에 적어 달라. | 에뮬레이터에서 일반·비행기 모드·빈 이미지 세 경우를 실행하고 측정값을 기록. |

## 2. 채택한 것

- 한국어 모델이 앱에 함께 들어가는 번들형 ML Kit Text Recognition. 실행 중 내려받기가 없어 비행기 모드 조건에 맞는다.
- 분석 전용 진입점 `analyzeOcr`를 기존 분석 함수와 따로 둔다.
- 처리 시간은 Kotlin 쪽에서 `SystemClock.elapsedRealtime()`으로 잰다. 채널 왕복 시간이 섞이지 않는다.

## 3. 고친 것과 판단

| 대상 | 바꾼 내용 | 이유 |
|---|---|---|
| 프로젝트에 있던 기존 분석 함수(개체 추출 포함) | 이번 화면에서는 부르지 않고 글자 인식만 쓰는 `analyzeOcr`를 사용 | 개체 추출 모델은 첫 실행 때 내려받아야 해서 비행기 모드 조건과 맞지 않는다. |
| 흰 이미지에서 0줄이 나오는 경우 | 실행해 본 뒤 오류가 아닌 정상 결과 `no_text`로 처리하고 안내 화면을 따로 둠 | 글자가 없는 것은 실패가 아니다. 사용자가 할 일(다시 찍기, 다른 이미지)을 알려 주는 편이 맞다. |
| AI가 쓴 README·결과 문구 | 그대로 내지 않고 빌드와 에뮬레이터 실행 결과에 맞춰 다시 정리. 처리 시간은 "각 1회 실행한 값"이라고 명시 | 실제로 한 번씩만 쟀다. |
