## 3. 원칙과 표시 규칙

**설계 기준 4원칙** [UI 2]
1. **사용자 주도** — 앱은 위치와 순서만 안내. 실제 입력·주문·결제는 사용자가 직접 한다. (테두리는 자동 클릭 영역이 아님) [UI 11~15]
2. **최소 수집** — 사용자가 고른 한 화면만 분석. 원본은 저장·외부 전송하지 않음.
3. **명확한 상태** — 스캔 대기 / 분석 중 / 권한 거부 / 실패 / 완료를 서로 다른 화면·문구로 구분.
4. **복구 가능** — 화면이 다르거나 인식 실패 시 재촬영, 다른 이미지, 현재 화면 재스캔 경로 제공.

**화면 표시 규칙** [UI 2]
- 안내 본문 16pt 이상, 목표 UI는 테두리·색상으로 강조 (단계 안내 화면은 "파란 테두리") [UI 11]
- 주황색 화면 테두리 = 안내 활성, 초록색 = 완료·개인정보 보호 상태
- 모든 화면 하단에 진행 표시: 입력 → 분석 → 기능 선택 → 안내 → 완료 [UI 전체]

**데이터 원칙** [BE 핵심 설계 원칙]
- 로컬 우선: 입력·분석·후보 검사·안내 생성은 기기 안에서
- 최소 수집: 서버에는 검수된 기능 맵과 사용자가 동의한 최소 이력만
- 검증 후 반영: 새 기능 맵은 버전·스키마·해시·서명 검증 후 로컬 DB에 원자적으로 반영
- 안전한 확장: 접근성·캡처·오버레이는 사용자 동의와 Android 권한 안에서만
- 실패해도 원본 전송으로 우회하지 않음 [BE 1, AI 1.1]

## 4. 기능 요구사항

### F01 화면 입력 (우선순위 상)
- **설명**: 카메라로 화면을 촬영하거나 갤러리에서 스크린샷·이미지를 불러오고, 분석 전 미리보기와 권한 안내를 제공 [명세 3]
- **입력 방식 3가지**: 카메라(CP→C→CR), 갤러리(G→GS→GR), 실시간 스캔(LP, N01) [UI 3]
- **세부 동작**
  - 정지 이미지 **1개**만 (C01). 갤러리는 한 장만 선택 가능, 선택 상태와 "선택한 이미지 사용" 버튼 표시 [UI 8]
  - 자기 폰 화면 = 스크린샷, 카메라 = 다른 기기 화면·실물 (C02)
  - 미리보기에서 "이 화면 분석하기" / "다시 촬영" 또는 "다른 이미지 선택" [UI 6, 9]
  - 카메라는 촬영할 때만 사용, 원본 미보관, 설정에서 권한 철회 가능함을 고지 [UI 5]
  - 갤러리 선택 시 위치 등 메타데이터 요청 안 함 (`requestFullMetadata: false`) [BE 3.1]
  - 반환값 구분: 성공 / **사용자 취소** / 권한 거부 / 파일 읽기 실패 [BE 3]
  - 앱이 만든 복사본만 필요 시 정리, **사용자 원본은 삭제하지 않음** [BE 3, TC-F01-05~07]
  - 불필요한 권한(위치·연락처 등)을 요청하지 않음 [TC-F01-09]
- **예외**: 권한 거부 → DENY(갤러리 등 다른 입력 경로 제공) [UI 27], 손상 이미지 → E [TC-F01-11]

### F02 온디바이스 UI 요소 분석 (상)
- **설명**: 원본을 외부로 보내지 않고 기기 안에서 버튼·메뉴·아이콘·텍스트를 인식·분석 [명세 3]
- **MVP 범위**: 텍스트가 있는 요소. 아이콘 전용 버튼은 확장(LiteRT 검출기, N01 접근성 노드) [AI 4.6]
- **결과**: 어떤 화면인지(화면 식별), 인식한 요소 목록, 각 요소의 위치(boundingBox = 강조 좌표) [AI 4.6, UI 7]
- **분석 중 화면**: "화면의 버튼과 메뉴 확인 / 개인정보 포함 가능성 확인 / 사용 순서 정리 중" 진행 표시, "분석 취소" 가능 [UI 6]
- **시간**: 목표 3초 이내 (NFR-02)
- **예외**: 화면 미식별·대상 후보 0개 또는 2개 이상·기능 맵에 없는 화면·어둡거나 기울어진 사진·글자 없는 아이콘 화면 → 추정하지 않고 "다시 촬영해 주세요" (C04) [AI 4.6, TC-F02]

### F03 개인정보 인식 및 주의 경고 (상)
- **설명**: 이름·연락처·주소·문서 내용 등 개인정보 포함 여부를 분석해 다른 앱 공유 전 주의 알림 [명세 3]
- **검출 대상**
  - ML Kit 개체 추출(한국어): 전화, 이메일, 주소, 결제카드, URL [AI 4.7]
  - 정규식(ML Kit에 없는 한국 형식): 주민·외국인등록번호, 휴대전화, 유선전화, 계좌번호 추정 [AI 4.7]
  - UI 설계서 P 화면 표기 대상: 얼굴·이름·연락처·주소·문서 내용 [UI 25] (얼굴·이름은 현재 채택 기술의 검출 대상에 없음 — 7장 참고)
- **처리 규칙**: 겹치는 후보 병합, 한국 형식 유형 우선, 전화 형식이면 계좌 후보 제외, 날짜 형식 제외 [AI 4.7]
- **표시**: 공유 전 확인 화면(P)에 "개인정보 후보 N건". **자동 삭제·자동 마스킹 안 함, 판단은 사용자** [AI 4.7]
- **주의 문구**: "검사는 주의를 돕는 기능이며 개인정보가 없음을 보증하지 않음" (C06) [UI 25]
- **실패**: ML Kit 실패·모델 미다운로드 → 정규식 결과만으로 진행. 후보 0건이어도 확인 화면 표시 [AI 4.7]
- 형식이 같은 다른 번호(13자리 주문번호 등)는 후보로 표시하고 사용자가 판단 [AI 4.7, TC-F03-07]

### F04 단계별 UI 사용 방법 안내 (상)
- **설명**: 사용자가 원하는 기능을 입력하면 관련 UI 요소를 찾아 단계별로 누를 위치와 방법을 안내 [명세 3]
- **기능 선택**: 글로 입력("치킨을 주문하고 싶어요") 또는 추천 기능 선택 [UI 7, 10]. MVP 구현 방식은 "기능 목록에서 선택 + 규칙 매칭" [AI 4.4]
- **단계 화면 구성** (D1~D5 공통) [UI 11~15]
  - 상단 "단계별 안내 · n / 전체", 기능 이름, "STEP 0n / 0N · 파란 테두리를 따라가세요"
  - 목표 UI 강조 + 안내 문구(무엇을 누를지) + 다음 상태 설명(누르면 무엇이 열리는지)
  - 버튼: "다음 단계"(마지막은 "안내 완료"), **"화면이 달라요 · 다시 분석"**
- **화면이 달라요**: 현재 화면을 다시 스캔하고 **같은 기능 ID의 새 UI 후보**를 찾음 [UI 11~15]
- **안내 문장**: 기능 맵의 단계를 템플릿으로 문장화 [AI 4.4]
- **마지막 단계**: 실제 주문·결제는 대상 앱에서 사용자가 직접 [UI 15]
- **예외**: 지원 범위 밖 앱·버전 → 좌표 강조 중단, 공식 도움말 또는 재스캔 안내 [UI 29], 지원하지 않는 기능 입력·빈 입력 [TC-F04-08·09]

### F05 사용 방법 및 분석 이력 저장 (중)
- **설명**: 확인한 기능과 단계별 안내 이력을 로컬에 저장. 원본 이미지 대신 분석 결과만 [명세 3, C03]
- **저장 시점**: DONE의 "안내 기록에 저장", P의 "안내 기록에 저장" [UI 16, 25]
- **조회**: HISTORY에서 입력 방식별 기록(카메라·갤러리·실시간) 다시 보기 [UI 26]. 앱 재시작 후에도 조회 [TC-F05-07]
- **선택적 동기화**: 사용자가 로그인·동의한 경우에만 **기능 ID·단계·시각**만 Firebase에 저장. 동의하지 않아도 F01~F04 핵심 기능은 동작 [BE 1.1, 6.1]
- 동기화 동의 화면에는 저장 필드·목적·철회 방법·로컬 이력 유지·삭제 정책을 표시 [BE 1.1]

### F06 분석 결과 및 가이드 공유 (중)
- **설명**: 분석된 UI 가이드·검증 결과를 메모·메시지·문서 앱 등 외부 앱으로 공유 [명세 3]
- **경로**: 어떤 진입점(RC, RG, DONE, HISTORY)에서든 **반드시 P(공유 전 확인)를 거쳐** SHARE로 [AI 1.1, TC-F06-04]
- **공유 내용**: 원본 이미지 없이 사용 방법 텍스트만 (예: "치킨 주문하기 · 사용 방법 1~5단계") [UI 25]. 공유 범위(분석 결과·검증 결과·단계별 사용 방법)는 사용자가 선택 [UI 25]
- **수단**: Android 공유 시트(share_plus) [AI 1.1]
- **취소**: P에서 "돌아가기" 가능 [UI 25, TC-F06-05]

### F07 UI 사용 흐름 테스트 확장 (하, 이번 범위 밖)
- 분석된 UI 요소로 특정 기능까지의 흐름 확인, 유스케이스 실행·버그 테스트로 확장 [명세 3]. C07에 따라 미구현.

### N01 요청형 실시간 오버레이 안내 (확장, Android 전용)
- **흐름**: 권한 동의(LP) → 다른 앱 위 AI 아이콘(L 닫힘 / LO 열림) → 원하는 기능 선택(LT) → 현재 화면 스캔(LX) → UI 테두리와 안내 패널(LG1~LG5) [UI 3, 17~24]
- **권한 3종을 각각 고지·철회 가능**: 접근성(버튼·메뉴 역할과 위치 읽기), 화면 위 표시(아이콘·테두리), 화면 캡처(요청한 한 화면만) [UI 17]
- **요청 시 스캔**: AI 아이콘을 누른 순간의 한 화면만 분석 [UI 20]
- **단계 진행**: 사용자가 목표 UI를 누르면 바뀐 화면을 다시 확인하고 다음 단계로 ("눌렀어요 · 다음 안내") [UI 21]
- **패널 위치**: 화면을 가리지 않는 위치 [UI 21]
- **종료**: "실시간 인식 끄기" 또는 권한 철회 시 오버레이와 캡처 서비스를 함께 즉시 종료, 자원 해제 [UI 20, BE 2.1]
- **Android 구성**: AccessibilityService(구조 조회), MediaProjection(화면 확보), WindowManager TYPE_APPLICATION_OVERLAY(표시) [BE 2.1]
- **자동 클릭 없음**, 낮은 신뢰도·버전 불일치에서는 추정 좌표 대신 재스캔·입력 변경 안내 [BE 2.1]

### B01 기능 정보 조회 / B02 버전 확인·다운로드 (백엔드)
- 두 기능은 같은 데이터 계약을 사용 [BE 5]
- **배포·검증·롤백 순서** [BE 5.2]
  1. 검수: 공식 자료로 기능 맵 작성, 출처·해시·검증일 기록 (실패 시 배포 안 함)
  2. 배포: revision·schema_version·해시·서명이 있는 패키지 공개 (실패 시 기존 revision 유지)
  3. 수신: 새 revision만 다운로드, 크기·필수 필드·버전 범위 검증 (실패 시 파일 폐기)
  4. 반영: 임시 테이블 저장 뒤 트랜잭션으로 기능 맵·활성 revision 교체 (실패 시 기존 유지)
- **실패 상황별 처리** [BE 6.3]: 새 revision 없음 → 유지 / 네트워크 단절 → 갱신 중단, 기존 사용 / 파일 손상·해시·서명 오류 → 폐기, 교체 금지 / 로그아웃·동기화 해제 → 클라우드 차단, 핵심 안내 유지
- **접근 규칙** [BE 6.2]: 공개(published) 기능 맵만 읽기, 앱의 쓰기 금지, 이력은 본인만 읽기·쓰기. 관리자 키는 앱에 넣지 않음

## 12. 설계 전에 짚어 둘 미확정·충돌 지점

설계하면서 결정해야 하는 부분이다. 문서끼리 표현이 다르거나 아직 정하지 않은 곳.

1. **기능 입력 방식**: UI 설계서는 자유 문장 입력("치킨을 주문하고 싶어요"), 채택 보고서 MVP는 "목록 선택 + 규칙 매칭". 자유 문장을 어디까지 받을지.
2. **개인정보 대상 범위**: UI 설계서 P는 얼굴·이름까지 표기, 채택 기술(ML Kit 개체 추출 + 정규식)은 얼굴·이름 검출 유형이 없음.
3. **분석 위치 표현**: 백엔드 보고서 8.1은 "Flutter 앱이 온디바이스 분석", 이후 채택 보고서는 "Kotlin 모듈이 분석". 최신 결정은 Kotlin.
4. **채널 응답 내용**: 문서는 "위치·유형만", 시험 앱은 인식 글자(label)를 함께 넘김. 화면에 표시할 짧은 라벨을 어디까지 허용할지.
5. **마스킹**: "자동 마스킹 안 함, 사용자 판단"이 결정. 공유 내용이 텍스트(사용 방법)뿐이라면 이미지 가림이 필요한지.
6. **공유 범위 선택**: UI 설계서는 분석 결과·검증 결과·단계별 사용 방법 중 선택. "검증 결과"의 실체가 F07(범위 밖)과 겹침.
7. **이력 동기화**: 선택 기능으로 문서화되어 있지만 MVP 구현 범위에 넣을지.
8. **실시간(N01) 인식 근거**: 접근성 노드 우선인지 OCR 우선인지 (UI 29는 접근성 우선, 채택 보고서 MVP는 OCR 중심).
9. **"화면이 달라요" 재스캔 입력**: 카메라·갤러리 경로에서 재스캔은 재촬영인지, 같은 기능 ID를 유지한 채 새 이미지를 받는 것인지.
10. **정규식 결함 수정**(`\b`)과 기기 위 재검증.
