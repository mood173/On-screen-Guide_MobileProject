## 2. 폴더 소유권

자기 폴더만 고친다. 남의 폴더를 고쳐야 하면 그 사람에게 요청한다.

```
lib/
  app/                         ← 지형주 (흐름 입구, 단계 설정표, 등록부, 셸)
  app/bootstrap.dart           ← 각자 자기 인터페이스 줄만
  shared/contracts/            ← 공동. 변경은 세 명 확인 (3장)
  shared/cells/, shared/theme/ ← 지형주
  shared/coordinate_mapper.dart ← 지형주 (순수 함수)
  features/
    capture/       domain/ ← 공동   data/ ← 최정혁   ui/, handlers/ ← 지형주
    analyze/       domain/ ← 공동   data/ ← 지형주(강민준과 협의)   ui/, handlers/ ← 지형주
    guide/         ui/, handlers/ ← 지형주
    privacy/       ui/ ← 지형주
    share/         domain/ ← 공동   data/ ← 최정혁   ui/, handlers/ ← 지형주
    history/       domain/ ← 공동   data/ ← 최정혁   ui/, handlers/ ← 지형주
    guidance_map/  domain/ ← 공동   data/ ← 최정혁
    settings/      ui/ ← 지형주
android/.../kotlin/...         ← 강민준
assets/feature_maps/           ← 최정혁 (스키마·형식) + 강민준 (실제 앱 맵 내용)
contract_fixtures/             ← 공동 (채널 예시 파일)
test/                          ← 자기 폴더에 대응하는 시험. test/ports/port_contracts.dart 는 공동
.github/workflows/             ← 최정혁
```

- 폴더는 **기능별**이다. 골격(`ccd7f84`)은 계층별이라 **11/13 전에 지형주가 한 번에 옮긴다.** 그때까지 못 옮기면 계층별로 확정하고 이후에는 옮기지 않는다.
- 기능 폴더 안에서 `data/`(저장·입출력)는 최정혁, `ui/`·`handlers/`(화면·버튼 처리)는 지형주, `domain/`(인터페이스·모델)은 공동이다.
- `bootstrap.dart`는 각자 **자기 인터페이스 줄만** 바꾼다.
- 브랜치는 `feat/<주제>`, `main`에 합치기 전에 본인이 아닌 한 명이 확인한다.

### 의존 규칙

| 규칙 | 확인 |
|---|---|
| `ui/`, `handlers/`, `app/`(bootstrap 제외)은 `data/`를 import하지 않는다 | import 검사 시험 1건 |
| 구현 클래스를 만드는 곳은 `app/bootstrap.dart`뿐이다 | 같은 시험 |
| 기능끼리는 서로의 `domain/`과 `shared/contracts/`만 본다 | 리뷰 |
| `features/privacy/`와 Kotlin 개인정보 검출 코드는 다른 기능을 보지 않는다 | 리뷰 |
| Kotlin을 부르는 Dart 코드는 `MethodChannelAnalyzer` 하나뿐이다 | 리뷰 |

## 3. 공동 계약

여기는 **세 사람이 같이 보는 약속**이다. 이름·필드를 바꾸면 모두 깨진다.

공통 규칙 넷.
1. 인터페이스의 메서드는 **예외를 밖으로 던지지 않는다.** 실패는 결과 값으로 돌려준다.
2. 시간이 걸리는 메서드는 `Future`를 돌려준다.
3. 주고받는 자료형은 만든 뒤 바뀌지 않는다.
4. 구현이 하나뿐인 순수 계산(좌표 변환, 공유 텍스트 만들기, 단계 맞추기)은 인터페이스로 만들지 않고 함수로 둔다.

### 3.1 인터페이스

```dart
// ── 분석 ─────────────── 구현: 강민준(Kotlin) + 채널 / 사용: 지형주
abstract interface class ScreenAnalyzer {
  Future<AnalysisResult> analyze(AnalyzeRequest request);
}

// ── 사진 가져오기 ────── 구현: 최정혁 / 사용: 지형주. 쓰는 쪽 기준으로 셋
abstract interface class GalleryInput {        // 갤러리 장면
  Future<PickStatus> requestAccess();           // ok 또는 permissionDenied
  Future<List<GalleryItem>> recent({int limit = 9});
  Future<PickedImage> use(String id);           // 고른 한 장을 앱 복사본으로 준비
}
abstract interface class CameraInput {         // 카메라 장면
  Future<PickedImage> takePhoto();              // 기기 기본 카메라 앱
}
abstract interface class InputCleanup {        // 흐름(세션 종료·앱 시작), 권한 안내 화면
  Future<void> release(PickedImage image);
  Future<void> clearLeftovers();
  Future<void> openAppSettings();
}

// ── 기능 맵 ──────────── 구현: 최정혁 / 사용: 지형주
abstract interface class GuidanceRepository {
  Future<GuidanceFragment> fragment();          // 지원하는 모든 화면의 앵커
  Future<List<GuideAction>> actionsFor(String screenId);   // 모르는 화면이면 빈 목록
  Future<String> activeRevision();
}
abstract interface class MapUpdater {
  Future<MapUpdateResult> checkForUpdate();     // 어떤 실패든 이전 맵 유지
}

// ── 기록 ─────────────── 구현: 최정혁 / 사용: 지형주
abstract interface class HistoryRepository {
  Future<void> save(HistoryEntry entry);        // 같은 id면 덮어쓴다
  Future<List<HistoryEntry>> list();            // 최근 것부터
  Future<HistoryEntry?> get(String id);
  Future<void> delete(String id);
}

// ── 공유 ─────────────── 구현: 최정혁 / 사용: 지형주
abstract interface class Sharer {
  Future<ShareOutcome> shareText(String text);  // 텍스트만. 이미지를 받는 메서드는 만들지 않는다
}
```

### 3.2 자료구조

```dart
// 입력
enum PickStatus { ok, cancelled, permissionDenied, readFailed }
enum InputKind { gallery, camera }              // 실시간이 붙으면 live
enum GalleryKind { photo, screenshot }          // 저장 폴더 이름이 Screenshots 인지로 판단 (관례)
class GalleryItem { String id; Uint8List thumbnail; GalleryKind kind; DateTime takenAt; }
class PickedImage { PickStatus status; String? path; InputKind input; }   // path = 앱 임시 폴더의 복사본

// 기능 맵 (화면·흐름이 보는 모양. 저장 스키마 FeatureMap 은 데이터 구현 안쪽)
class GuideAction { String actionId; String screenId; String title; String description; List<GuideStep> steps; }
class GuideStep   { String screenId; String selector; String instruction; String result; }
enum MapUpdateStatus { upToDate, updated, offline, rejected }
class MapUpdateResult { MapUpdateStatus status; String revision; }

// 기록 — 원본 이미지·화면에서 읽은 글자·개인정보 후보 값을 담는 칸은 없다
class HistoryEntry {
  String id; String actionId; String actionTitle;
  List<String> stepInstructions; InputKind input; DateTime createdAt;
  List<String> piiTypes;                        // 유형 이름만
}

// 공유
enum ShareOutcome { sent, dismissed, failed }
```

기능 맵 규칙 (공용 시험 `guidanceRepositoryContract`로 확인).

| 규칙 | 이유 |
|---|---|
| 화면 ID는 `앱.화면`(예: `baemin.home`), 전체에서 겹치지 않는다 | 스크린샷만으로는 어느 앱인지 알 수 없다. 맵 조각에 모든 지원 화면을 담는다 |
| 화면마다 앵커 2개 이상, 앵커끼리 서로 포함하지 않는다 | 한 줄이 앵커 두 개로 세어지는 것을 막는다 |
| 기능 ID는 `영역.동작`, 겹치지 않는다 | 계약 v1 결정 2 |
| 기능마다 단계 1개 이상 5개 이하 | 단계 화면이 D1~D5 |
| 단계의 `screenId`는 맵 조각에 있는 화면이고, 첫 단계의 화면 = 기능의 시작 화면 | 단계가 다른 화면에 걸칠 수 있다 |
| 선택자는 2자 이상, 실제 OCR 결과에서 **한 줄로 읽히는 글자** | 한 글자는 오인식 허용이 안 되고, 대상 찾기는 줄 전체와 비교한다 |

### 3.3 강민준 ↔ 최정혁 경계 — 채널과 맵

**맵은 Flutter가 들고, Kotlin은 상태 없이 분석만 한다.** 두 사람은 직접 주고받지 않는다. 맵 조각은 최정혁의 저장소 → 지형주의 흐름 → 채널 요청으로 간다.

채널 `screen_guide/analyze` · 메서드 `analyze`. 요청·응답 JSON은 개발 계약 v1 결정 1 그대로다 (`shared/contracts/analysis.dart`, 예시 파일 `contract_fixtures/analyze/`).

| 필드 | 규칙 |
|---|---|
| `imagePath` | 앱 임시 폴더의 **파일 경로** 한 가지 |
| `guidance.screens[]` | 지원하는 모든 화면의 `screenId`와 `anchors` |
| `guidance.packageName` | 이미지 입력에서는 빈 문자열. 실시간이 붙으면 현재 앱 [제안] |
| `target` | 기능을 고르기 전에는 뺀다. 단계 안내에서는 그 단계의 `selector` |
| `status` / `errorCode` | 실패는 **응답 본문**으로 알린다. Kotlin이 내는 코드는 `NO_PATH`, `IMAGE_READ_FAILED`, `ANALYSIS_FAILED` (대문자) |
| `box` | 원본 이미지 픽셀 `[left, top, right, bottom]` |
| `imageSize` | 화면에 보이는 방향 기준의 크기 (세로로 찍은 사진은 회전 뒤 값) |
| `screenId` | 식별 못 하면 `null` |
| `target` (응답) | 요청에 없었거나, 후보가 0개 또는 2개 이상이면 `null` |
| `pii[].type` | 아래 9개 값 중 하나. 엔진 이름을 붙이지 않는다 |
| `pii[].masked` | 앞 3자·뒤 2자만 남긴 값 |
| `piiEngine.mlkit` | `failed`여도 정규식 결과로 진행 |

개인정보 유형 9개: `주민·외국인등록번호`, `휴대전화`, `유선전화`, `계좌번호 추정`, `전화`, `이메일`, `주소`, `카드`, `URL`.

분석 규칙 (Kotlin이 기준, 가짜 분석기는 같은 규칙의 복사본).

| 규칙 | 내용 |
|---|---|
| 화면 식별 | 앵커 2개 이상이 **서로 다른 요소**에서 맞아야 한다. 여러 화면이 맞으면 맞은 수가 가장 많은 화면, 같은 수면 식별하지 않는다 |
| 대상 찾기 | 정확히 같은 요소가 **하나일 때만**. 없으면 길이가 같고 한 글자만 다른 요소가 하나일 때만. 그 밖은 없음 |
| 넘기지 않는 것 | 원본 이미지, 화면에서 읽은 글자 전체, 개인정보 후보 원문. Logcat에도 찍지 않는다 |
| 네트워크 | 사용자 이미지와 글자는 나가지 않는다. OCR 모델은 앱에 들어 있다. 개체 추출 모델은 첫 실행 때 내려받고, 없으면 기다리지 않고 정규식만 쓴다 |

### 3.4 지형주 ↔ 최정혁 경계

- 지형주는 **인터페이스 타입만** 안다. 구현 클래스를 직접 만들지 않는다.
- 결과 값을 받아 화면을 고르는 것은 지형주, 권한 확인·요청·설정 열기 동작은 최정혁.
- 포트의 결과를 오류 코드와 화면으로 바꾸는 표:

| 결과 | 흐름이 하는 일 |
|---|---|
| `PickStatus.cancelled` | 그 자리 유지 |
| `PickStatus.permissionDenied` | 권한 안내 화면 (`PERMISSION_DENIED`). 거부된 입력 방식을 세션에 기록 |
| `PickStatus.readFailed` | 오류 화면 (`IMAGE_READ_FAILED`) |
| 분석 `status: error` | 오류 화면 (응답의 코드 그대로) |
| 분석 `screenId` 없음 | 오류 화면 (`UNKNOWN_SCREEN`) "다시 촬영해 주세요" |
| 분석 `target` 없음 (화면은 맞음) | 오류 화면 (`NO_TARGET`) |
| 단계의 화면 ≠ 지금 이미지의 화면 | 오류가 아니다. 글 안내 카드 |
| `ShareOutcome.dismissed` | 들어온 곳으로 |
| `ShareOutcome.failed` | "공유하지 못했어요" 뒤 들어온 곳으로 |
| `MapUpdateStatus.offline` / `rejected` | 아무것도 막지 않는다 |

- 호출 시점 (지형주가 지킨다):

| 무엇 | 언제 |
|---|---|
| `InputCleanup.clearLeftovers` | 앱 시작 |
| `InputCleanup.release` | 세션이 끝날 때 (홈으로, 다시 고르기, 오류 뒤 떠남, 새 화면으로 바꿀 때) |
| `HistoryRepository.save` | 마무리(안내 완료)에서만 |
| `Sharer.shareText` | 공유 전 확인 화면을 거친 뒤에만. 들어오는 곳은 마무리와 기록 |
| `MapUpdater.checkForUpdate` | 앱 시작. 결과를 기다리지 않는다 |

- 단계가 다른 화면에 걸칠 때 (지형주, 순수 함수 하나):

```
사용자가 화면을 올렸고 그 화면의 ID가 s, 지금 단계가 n일 때
  ① n 이후(n 포함)에서 screenId == s 인 첫 단계로 이동
  ② 없으면 n 이전에서 screenId == s 인 마지막 단계로 이동
  ③ 그래도 없으면 "이 기능의 화면이 아니에요"
```

### 3.5 버튼 ID (`ActionId`)

"ID 하나 = 뜻 하나"다. 계약 v1의 23개에 5개(★)를 더한다.

```dart
enum ActionId {
  // 입력
  captureCamera, captureGallery, capturePick /*★ 목록 한 칸 */, captureConfirm /*★ 선택한 이미지 사용 */, captureRetake,
  // 분석
  analyzeRun, analyzeCancel,
  // 안내
  guideStart, guideNext, guidePrev, guideMismatch,
  // 공유·개인정보
  sharePrepare, shareConfirm, shareSend,
  // 기록
  historySave, historyOpen /* 한 건 */, historyDelete /*★*/, syncToggle,
  // 설정·권한·이동
  settingsOpenPermission /* 기기 권한 설정 */, navHome, navBack, navHistory /*★ 기록 화면 */, navSettings /*★ 설정 화면 */,
  // 기능 맵
  mapCheck,
  // 오버레이 (자리만)
  overlaySetup, overlayStart, overlayStop, overlayRescan,
}
```

| ID | 처리하는 핸들러가 부르는 것 |
|---|---|
| `captureGallery`, `capturePick`, `captureConfirm` | `GalleryInput` |
| `captureCamera` | `CameraInput` |
| `captureRetake` | 세션의 입력 방식에 따라 위 둘 중 하나 |
| `analyzeRun`, `guideStart`, `guideNext`, `guidePrev` | `GuidanceRepository`, `ScreenAnalyzer` |
| `guideMismatch` | 입력 → 분석 → 단계 맞추기 |
| `sharePrepare`, `shareConfirm` | (흐름 안) 확인 화면과 관문 |
| `shareSend` | `Sharer` |
| `historySave`, `historyOpen`, `historyDelete` | `HistoryRepository` |
| `settingsOpenPermission` | `InputCleanup.openAppSettings` |
| `mapCheck` | `MapUpdater` |

새 버튼이 필요하면 이 표에 먼저 추가한다 (세 명 확인).

### 3.6 상태 관리 (계약 v1 결정 3)

`ChangeNotifier`와 바뀌지 않는 상태 클래스, 화면은 `ListenableBuilder`, 주입은 `bootstrap()`의 생성자 주입. 외부 패키지는 쓰지 않는다. 세션 값(입력 방식, 이미지, 분석 결과, 기능, 단계 번호, 개인정보 후보, 확인 여부, 오류, 거부된 입력 방식)은 흐름이 가진다. 화면은 값을 받아 그리고, 버튼의 켜짐·꺼짐은 관문(`flow.allows`)이 정한다.
