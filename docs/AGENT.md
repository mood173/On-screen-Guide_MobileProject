## 제출 형식

- 단계별 ZIP 최상위에 `app/`, `README.md`, `screenshots/`, `prompts_log.md`를 바로 둔다. MP3는 `PRIVACY.md`도 최상위에 둔다.
- `app/`은 실행 가능한 Flutter 프로젝트 소스다. `.env`, 비밀키, `.dart_tool`, `build`, `.gradle`, `node_modules` 및 설치·생성 폴더를 ZIP에서 제외한다.
- 스크린샷은 실제 Android 기기/에뮬레이터 화면만 사용하고 출처를 README에 적는다. 생성 시안은 동작 증거로 쓰지 않는다.
- 업로드 전 ZIP을 다시 열어 항목과 제외 파일, 사이트의 현재 용량 제한(과제 안내 기준 20MB)을 확인한다. 업로드 후 접수 상태는 작업 기록에 남긴다.

## 실패 조사와 검증

- 실패한 사용자 동작과 기대 결과를 먼저 고정하고 화면 → 입력 → MethodChannel → Kotlin/ML Kit 또는 저장 → 응답 → 화면의 같은 요청을 추적한다.
- 코드상 예상, 실제 관측, 미확정 가설을 구분한다. 로그 부재를 미도착으로 단정하지 않는다. 빌드·단위시험·별도 샘플 성공을 실제 기능 통과로 대체하지 않는다.
- 검사 전에 구분할 가설, 최소 관측, 성공·중단 조건을 정한다. 새 증거 없이 같은 시험을 반복하지 않는다. 동일 문제를 두 번 해결 시도해도 남으면 세 번째 시도 전에 사용자에게 확인 사실·미확정 경계·다음 선택지를 보고한다.
- 사용자 원본 이미지와 개인정보는 외부에 올리지 않는다. 단계별 스냅샷과 ZIP은 검증된 소스·문서·증거 화면을 일치시킨다.
