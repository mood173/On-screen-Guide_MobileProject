# 화면길잡이 미니프로젝트 공통 작업 지침

## 프로젝트와 범위

- 대상 저장소: `D:\dev\On-screen-Guide_MobileProject`
- 실행 앱: `screen_guide_test/` (Flutter Android 앱, 기존 Kotlin ML Kit 시험 코드 포함)
- 과제: AI-ANT **사진 인식 앱 2107번** 미니프로젝트. 현재 작업은 **1단계: 카메라와 권한 다루기**에 한정한다.
- 2108 피드 화면 가이드와 라즈베리파이 미니프로젝트 공지 PDF는 별도 과제다. 이 프로젝트의 구현·평가 기준으로 쓰지 않는다.
- Claude Code 사용 안내는 도구 예시다. Codex에서도 같은 소스, 실행 결과, 제출물 기준으로 작업한다.

## 1단계 완료 기준

1. 카메라 촬영 또는 갤러리 선택으로 정지 이미지 한 장을 가져온다.
2. 선택한 이미지가 미리보기와 결과 화면에 표시된다.
3. 카메라 권한 요청, 거부 시 안내, 설정 또는 다른 입력 방식으로 회복하는 흐름이 있다.
4. 취소, 파일 읽기 실패, 표시 실패에서 앱이 종료되지 않는다.
5. `README.md`에 실행 절차와 권한·예외 처리를 설명한다.
6. 실제 기기 또는 에뮬레이터의 이미지 표시, 권한 요청, 거부 안내 화면을 캡처한다. 캡처가 없으면 완료로 보고하지 않는다.
7. `prompts_log.md`에 사용한 주요 프롬프트와 AI 응답의 채택·수정 내역을 기록한다.

제출 ZIP 최상위에는 `app/`, `README.md`, `screenshots/`, `prompts_log.md`를 둔다. `.env`, `.dart_tool`, `build` 등 설치·생성 파일은 제외한다. 사이트 업로드 전 ZIP 내부 구조와 용량을 확인한다.

## 기술 구조

`Flutter UI → image_picker → 카메라/사진 선택기 → 파일 경로 → 이미지 미리보기·표시`가 1단계의 사용자 흐름이다. 기존 `Flutter → MethodChannel → Kotlin Analyzer → ML Kit`는 이후 단계용 시험 기능이며 1단계 통과를 대신하지 않는다. 기존 분석 코드를 수정해야 할 때는 동작 영향과 이유를 먼저 기록한다.

자료: `docs/공통_최종설계문/화면길잡이_기능_개념_정리.md`, `docs/공통_최종설계문/화면길잡이_시험제작_가이드.md` 및 별도의 중간보고서 원본. 보고서의 전체 앱 구상과 현재 과제 1단계를 구분한다. 사이트 과제 화면의 최신 제출 요구를 우선 확인한다.

## 공통 작업 규칙

- 실패 조사에서는 사용자 동작 하나와 기대 결과를 고정하고, 화면 → 이미지 선택기 → 파일 → 표시의 같은 요청 경로를 추적한다. 코드상 예상, 실제 관측, 미확정 가설을 구분한다.
- 실제 기기에서 확인하지 않은 경로를 통과했다고 쓰지 않는다. 별도 샘플·모의시험·빌드 성공은 카메라나 권한 흐름의 실제 성공을 증명하지 않는다.
- 검사 전 구분할 가설, 최소 관측, 성공·중단 조건을 정한다. 새 증거 없이 같은 시험을 반복하지 않는다.
- 동일 문제를 두 번 해결 시도해도 남으면 세 번째 시도 전에 사용자에게 확인 사실, 미확정 경계, 다음 선택지를 짧게 보고한다.
- 사용자 원본 이미지와 개인 정보를 외부에 올리지 않는다. 비밀키, `.env`, 생성 폴더를 제출 ZIP에 넣지 않는다.
- 작업 전에 이번 미니프로젝트 날짜 폴더의 `AGENT.md`를 읽고, 프롬프트·AI 답변·변경 결과·검증 상태를 해당 폴더에 남긴다.
