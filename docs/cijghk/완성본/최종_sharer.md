# 최종 · Sharer (사용 방법 텍스트를 시스템 공유 시트로)

2026-11-21 · 최정혁 · 브랜치 `feat/history-db` (로컬, 아직 PR 전)
작업 기록: `../ai_log/2026-11-21_sharer.md` · 설계: `../데이터_입출력_설계.md` 6-2

## 하는 일

공유 전 확인(P)을 거친 **사용 방법 텍스트**를 Android 시스템 공유 시트로 보내 메모·메시지 앱 등에 넘긴다. **텍스트만** 보낸다 — 이미지를 받는 메서드는 없다.

## 쓰는 법

| 항목 | 내용 |
|---|---|
| 포트 | `Sharer.shareText(text)` → `ShareOutcome { sent, dismissed, failed }` |
| 구현 | `lib/features/share/data/share_plus_sharer.dart` — `SharePlusSharer` (`share_plus` 13.3) |
| 조립 | `app/bootstrap.dart`: `sharer: SharePlusSharer()` |
| 부르는 곳 (규격 3.4) | 공유 전 확인 화면을 거친 뒤 SHARE의 `shareSend`에서만 (지형주). 들어오는 곳은 마무리와 기록 |

## 결과

| 상황 | `ShareOutcome` | 흐름이 하는 일 (규격 3.4) |
|---|---|---|
| 사용자가 공유할 앱을 고름 | `sent` | — |
| 공유 시트를 닫음 | `dismissed` | 들어온 곳으로 |
| 시트는 열렸지만 결과를 알 수 없음 (`unavailable`) | `sent` **[제안]** | — |
| 빈 텍스트, 시트를 열지 못함, 그 밖의 오류 | `failed` | "공유하지 못했어요" 뒤 들어온 곳으로 |

예외를 밖으로 던지지 않는다. Android는 "앱을 골랐다"까지만 알려 주므로, 고른 앱에서 실제로 보냈는지는 알 수 없다.

## 확인

- 시험: 단위 4건(결과 변환, 텍스트 그대로 전달, 빈 텍스트, 예외) + 공유 공용 시험 3건.
- Android 36 에뮬레이터: 시스템 공유 시트가 열리고 텍스트 미리보기가 보낸 글 그대로, 닫으면 `dismissed`, 앱을 고르는 것도 동작(사용자 확인). 비정상 종료 0건. **실기기 미확인.**

## 한계와 팀 확인

- `unavailable` → `sent` 변환은 팀 확인 필요 (설계 문서 9장 6번).
- 보내는 텍스트에 인식 글자·가린 값이 섞이지 않게 하는 것은 공유 텍스트를 만드는 함수와 그 시험의 몫이다 (이 구현은 받은 텍스트를 그대로 보낸다).
