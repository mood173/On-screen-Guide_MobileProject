기준: `화면길잡이_협업규격_최종`(3·4장), `시스템설계_최종`, `일정_현실검토`(조정안, 11/13 팀 확인 전), 골격 `screen_guide/` (main `57f4c74`)
표시: **[제안]** = 아직 팀이 확인하지 않은 것. **[확인 필요]** = 구현 전에 정해야 하거나 직접 확인해야 하는 것. 표시가 없으면 규격·골격에 이미 있는 것이다.

> 이 문서가 답하는 것: **내 담당(데이터·입출력)을 어떤 구조로, 어떤 순서로, 무엇을 써서 만들고, 어떻게 확인하는가.**
> 인터페이스(포트)의 이름·서명은 규격 3장 그대로이고 이 문서가 바꾸지 않는다. 구현이 포트 안쪽에서 어떻게 생겼는지를 정한다.

## 3. 구조

### 3-1. 폴더 (내 파일만)

```
screen_guide/
  assets/feature_maps/
    schema_v1.json             ← 맵 스키마 (JSON Schema)
    sample_v1.json             ← 형식 확인용 맵 (실제 맵은 강민준 내용으로 교체)
  lib/features/
    capture/data/
      picker_camera_input.dart
      media_gallery_input.dart
      file_input_cleanup.dart
      app_copy_files.dart       ← 앱 복사본 만들기·지우기 (sg_ 규칙). 포트가 아니라 내부 도구
    guidance_map/data/
      feature_map.dart          ← 저장 스키마 모양 (FeatureMap, AppGuide, ScreenDef, ActionDef, StepDef)
      feature_map_codec.dart    ← JSON ↔ FeatureMap, 검증
      asset_guidance_repository.dart
    history/data/
      sqlite_history_repository.dart
    share/data/
      share_plus_sharer.dart
  test/ports/                   ← 공용 시험에 내 구현을 한 줄씩 추가
  test/features/<기능>/data/    ← 내 구현 전용 시험
.github/workflows/ci.yml        ← (시간이 될 때)
```

`feature_map.dart`의 저장 모양은 규격 7장 "원래 계약에서 달라진 곳"대로 **데이터 구현 안쪽**에서만 쓴다. 바깥(화면·흐름)에는 `GuideAction`·`GuideStep`·`GuidanceFragment`만 나간다.

### 3-2. 의존 패키지 [제안]

`pubspec.yaml`은 공용 파일이다. 추가할 때 PR에 이유를 적고 팀에 알린다. 버전은 추가하는 날 최신 안정판을 확인해서 고른다.

| 용도 | 후보 | 이유 | 상태 |
|---|---|---|---|
| 카메라·(대체) 갤러리 | `image_picker` | 1단계 미니프로젝트(`screen_guide_test`)에서 이미 쓰고 시험함 | 확정에 가까움 |
| 갤러리 최근 목록·썸네일 | `photo_manager` | 앨범 이름(Screenshots) 조회, 썸네일, 권한 상태를 한 패키지로. `image_picker`는 목록을 주지 않는다 | **[확인 필요]** 에뮬레이터에서 직접 확인 |
| 임시 폴더 | `path_provider` 또는 `dart:io`의 `Directory.systemTemp` | 골격이 이미 `systemTemp`의 `sg_` 폴더를 쓴다. 그대로 이어가는 쪽이 단순하다 | 유지 제안 |
| 기록 DB | `sqflite` + `path` | 기록은 단순한 표 하나다. 코드 생성 도구가 필요 없다 | [제안] |
| 공유 | `share_plus` | 개념 정리·채택 기술 보고서가 정한 것 | 확정 |
| 권한 설정 열기 | `app_settings` | 앱 정보(권한) 화면을 여는 작은 패키지. 추가 권한 없음, MIT. Kotlin 채널을 새로 만들면 규격 2장 "Kotlin을 부르는 Dart 코드는 `MethodChannelAnalyzer` 하나뿐"에 어긋난다 | 확정 (11/13) |

갤러리 목록을 Kotlin(MediaStore)에서 받아오는 방법도 있지만 `android/`는 강민준 소유이고 시간이 더 든다. `photo_manager`가 에뮬레이터에서 안 되면 그때 상의한다.

## 4. 입력 (`CameraInput`, `GalleryInput`, `InputCleanup`)

### 4-1. 공통: 앱 복사본 (`app_copy_files.dart`)

- 가져온 사진은 **앱 임시 폴더의 `sg_*` 폴더에 복사**하고, 그 파일 경로가 `PickedImage.path`다. Kotlin 분석 요청의 `imagePath`로 그대로 간다.
- 골격의 `CacheImageFiles`와 같은 규칙: `Directory.systemTemp.createTemp('sg_')` 아래 파일 하나, 삭제는 부모 폴더 이름이 `sg_`를 포함할 때만.
- 사용자 원본은 읽기만 하고 수정·삭제하지 않는다.
- 복사 중 `FileSystemException` → `PickStatus.readFailed`.

### 4-2. `CameraInput.takePhoto()` — 11/18

| 상황 | 처리 | `PickStatus` |
|---|---|---|
| 촬영 성공 | 결과 파일을 앱 복사본으로 만들고 경로 반환 | `ok` |
| 사용자가 카메라를 닫음 | `pickImage`가 `null` | `cancelled` |
| 카메라 권한 거부 (`camera_access_denied`, `camera_access_denied_without_prompt`) | 예외를 잡아 변환 | `permissionDenied` |
| 파일이 없거나 비었음, 복사 실패, 그 밖의 `PlatformException` | | `readFailed` |

- 1단계 `screen_guide_test/lib/main.dart`의 `_pick`·`_handlePickerError`가 이미 위 구분을 구현·검증했다(에뮬레이터 캡처 있음). **그 논리를 포트 모양으로 옮기고**, 화면 상태 변경은 모두 뺀다.
- `requestFullMetadata: false`로 위치 메타데이터를 요청하지 않는다.
- 기기에 카메라 앱이 없거나 에뮬레이터 카메라가 꺼진 경우도 `readFailed`로 돌려준다 [확인 필요: 실제 반환 코드].
- **카메라 권한은 매니페스트에 선언한다** (기능별_검토_결론 1-3 "결론"). 선언해야 권한 요청·거부 흐름(CP → DENY)이 생기고 1단계 제출물과 같아진다. `screen_guide/android/`의 매니페스트에는 아직 없다. `android/`는 강민준 소유라 **추가를 요청**한다. 선언 전에는 기본 카메라 앱이 권한 없이 열리므로 `permissionDenied`가 나오지 않는다.
- 찍은 뒤 image_picker가 앱 캐시에 남긴 원본은 복사본을 만든 뒤 지운다. 앱 데이터 폴더 안의 파일일 때만 지운다(사용자 갤러리 파일은 지우지 않는다).
- 구현: `lib/features/capture/data/picker_camera_input.dart`, `app_copy_files.dart` (11/12, `feat/camera-input`)

### 4-3. `InputCleanup` — 11/20

| 메서드 | 동작 |
|---|---|
| `release(image)` | `image.path`가 앱 복사본(`sg_`)일 때만 그 폴더를 지운다. 경로가 없거나 사용자 원본 경로면 아무것도 하지 않는다. 이미 없어도 오류 없음 |
| `clearLeftovers()` | 앱 시작 때 임시 폴더의 `sg_*` 폴더를 모두 지운다. 읽거나 지우지 못한 것은 다음 시작 때 다시 시도 |
| `openAppSettings()` | 기기의 앱 권한 설정 화면을 연다. 실패해도 예외 없이 끝난다 |

`openAppSettings`는 `app_settings` 패키지로 연다 (11/13 결정). Kotlin 채널을 새로 만들지 않는 이유는 위 3-2 표.

- 구현: `lib/features/capture/data/file_input_cleanup.dart` (11/13, `feat/camera-input`)
- `clearLeftovers`는 `sg_` 복사본과 함께, image_picker가 앱 `cache/`에 남긴 파일(카메라 취소 때의 0바이트 파일, 촬영 중 종료된 사진)도 지운다. 캐시 폴더 바로 아래이고 이름이 image_picker 모양(UUID + 숫자 + 이미지 확장자)인 파일만. Android에서만 동작한다.

### 4-4. `GalleryInput` — 11/20

| 메서드 | 동작 |
|---|---|
| `requestAccess()` | 사진 접근 권한을 확인하고 필요하면 요청. 허용 `ok`, 거부 `permissionDenied`. 일부 사진만 허용한 상태도 `ok`로 보고 목록은 허용된 것만 보여 준다 [확인 필요] |
| `recent({limit = 9})` | 최근 사진·스크린샷을 최근 순으로 최대 `limit`장. 썸네일은 작은 크기만. 앨범 이름이 `Screenshots`(또는 기기별 동등 이름)이면 `GalleryKind.screenshot`, 아니면 `photo`. 권한이 없으면 빈 목록 |
| `use(id)` | `id`의 원본을 읽어 앱 복사본으로 만들고 `PickedImage` 반환. 모르는 id·삭제된 사진·읽기 실패는 `readFailed` |

- 스크린샷 판별은 **관례**라 기기에 따라 틀릴 수 있다(규격 3.2에 이미 적힌 한계). 틀려도 동작에는 영향이 없고 배지만 달라진다.
- 목록에 `id`와 썸네일, 종류, 촬영 시각만 담는다. 원본 경로는 화면에 넘기지 않는다.
- 이미지는 한 장만(제약 C01). 여러 장 선택은 만들지 않는다.
- 권한을 영구 거부한 경우와 처음 거부한 경우의 구분이 필요한지는 지형주의 권한 안내 화면과 맞춘다. 포트에는 `permissionDenied` 하나뿐이다.

### 4-5. 갤러리가 11/20에 안 될 때

규격 5장 "늦어질 때"를 따른다: 카메라만 진짜로 끼우고 갤러리는 가짜(샘플)로 한 주 더 간다. 11/20 결합의 최소 통과선은 "카메라 한 장 → 분석 → 결과 화면"이다.

## 5. 기능 맵 (`GuidanceRepository`)

### 5-1. 파일 형식 `sample_v1.json` / 실제 맵 [제안]

```json
{
  "schemaVersion": 1,
  "revision": "2026-11-20.1",
  "apps": [
    {
      "packageName": "com.example.demo",
      "locale": "ko-KR",
      "versionMin": null,
      "versionMax": null,
      "screens": [
        { "screenId": "demo.settings", "anchors": ["네트워크 및 인터넷", "알림 설정", "배터리", "디스플레이"] }
      ],
      "actions": [
        {
          "actionId": "settings.notification",
          "title": "알림 설정 바꾸기",
          "description": "앱별 알림을 켜고 끄는 화면으로 가요",
          "supportLevel": "verified",
          "steps": [
            {
              "screenId": "demo.settings",
              "selector": "알림 설정",
              "instruction": "알림 설정을 눌러주세요",
              "result": "앱별 알림을 켜고 끌 수 있는 화면이 열려요."
            }
          ]
        }
      ]
    }
  ]
}
```

- 필드 이름은 협업 계약 초안 3.2의 `FeatureMap`·`AppGuide`·`ScreenDef`·`ActionDef`·`StepDef`를 따르고, 단계의 `nextHint`는 골격이 쓰는 이름 `result`로 한다(규격 7장).
- `ActionDef.screenId`(기능의 시작 화면)는 파일에 적지 않고 **첫 단계의 `screenId`에서 얻는다**. 같은 값을 두 곳에 적어 어긋나는 것을 막는다 [제안].
- 대상 앱이 11/15에 정해지면 `packageName`·화면 ID가 확정된다. 그전에는 골격의 체험용 맵(`demo.settings`, `demo.chat`)과 같은 내용으로 `sample_v1.json`을 만들어 같은 시험을 통과시킨다.

### 5-2. 읽기와 검증 (`feature_map_codec.dart`)

1. 앱 에셋에서 JSON을 읽는다 (`rootBundle`).
2. `schemaVersion`이 1인지, 필수 필드(`revision`, `apps`, `screenId`, `anchors`, `actionId`, `steps`, `selector`, `instruction`)가 모두 있는지 확인한다. **하나라도 없으면 그 맵 전체를 거부**한다.
3. 규격 3.2 표의 규칙을 지키는지 확인한다: 화면 ID 형식·유일성, 앵커 2개 이상·서로 포함 금지, 기능 ID 형식·유일성, 단계 1~5개, 단계 화면이 맵에 존재, 선택자 2자 이상.
4. 통과한 맵을 `FeatureMap`으로 들고, `fragment()`·`actionsFor()`·`activeRevision()`에 답한다.

**실패 처리**: `fragment()`와 `actionsFor()`는 예외를 던지지 않는다(규칙 1). 맵을 못 읽거나 검증에 실패하면 **내장 맵**으로 돌아간다 — 내장 맵은 앱에 든 `sample_v1.json` 자체이거나 코드에 박은 최소 맵이다 [제안: 앱에 든 JSON이 곧 내장 맵이므로 별도 폴백은 만들지 않고, 이 파일이 깨지면 시험이 먼저 실패하게 한다]. 모르는 화면은 `actionsFor`가 빈 목록을 돌려준다.

### 5-3. 맵 시험 보강

골격의 `guidanceRepositoryContract`는 **읽은 결과**의 규칙(화면·기능·단계)을 확인한다. 내가 더하는 시험은 **파일 쪽**이다.
- `schema_v1.json`으로 `sample_v1.json`과 실제 맵 파일을 검증한다.
- 필수 필드가 빠진 JSON, 앵커가 서로 포함된 JSON, 단계가 6개인 JSON이 거부되는지.
- 이 시험은 맵 파일을 강민준이 고칠 때마다 CI에서 돈다(CI가 없으면 `flutter test`로 확인).

## 6. 기록과 공유

### 6-1. `HistoryRepository` — 11/27

테이블 하나 [제안]:

| 열 | 타입 | 내용 |
|---|---|---|
| `id` | TEXT, 기본키 | 같은 id로 `save`하면 덮어쓴다 |
| `action_id` | TEXT | 기능 ID |
| `action_title` | TEXT | |
| `step_instructions` | TEXT | 단계 문구 목록 (JSON 문자열) |
| `input` | TEXT | `gallery` / `camera` |
| `created_at` | INTEGER | 시각 |
| `pii_types` | TEXT | 개인정보 **유형 이름**만 (JSON 문자열) |

- **이미지 경로·인식 글자·가린 값을 담는 열을 만들지 않는다.** 규격이 정한 `HistoryEntry`와 열이 1:1이다.
- `list()`는 `created_at` 내림차순. `get`은 없으면 `null`. `delete`는 없는 id여도 오류 없음.
- 저장·읽기에 실패하면 예외 대신 `save`·`delete`는 조용히 실패하고 `list`는 빈 목록, `get`은 `null`을 돌려주되 [확인 필요: 저장 실패를 흐름이 알아야 하는지 — 포트에 결과 값이 없다. 지형주와 상의].
- 앱을 껐다 켜도 남는지를 에뮬레이터에서 확인한다(규격 4.3 완료 기준).
- 동의 시 서버 동기화는 이번 범위에 넣지 않는다(규격 8장 8번 미정, 일정 검토 설정 화면 축소).

### 6-2. `Sharer` — 11/27

| 결과 | 조건 |
|---|---|
| `sent` | 사용자가 앱을 골라 보냄 |
| `dismissed` | 공유 시트를 닫음 |
| `failed` | 공유 시트를 열지 못함, 예외 |

- 텍스트만 보낸다. 이미지·파일을 받는 메서드는 만들지 않는다.
- 공유 시트의 결과 상태가 기기·앱에 따라 `sent`와 `dismissed`를 구분하지 못할 수 있다 [확인 필요: `share_plus`의 결과 상태가 안드로이드에서 어떻게 오는지 직접 확인]. 구분이 안 되면 규격의 세 값 중 어디로 맞출지 지형주와 정한다.
- 공유 전 확인(P) 화면을 거치는 것은 흐름의 관문이 보장한다. 내 구현은 그것을 모르고 받은 텍스트를 보내기만 한다.

## 7. 시험과 교체 절차

각 구현마다 같은 순서를 따른다 (규격 6장).

1. 내 브랜치에서 구현한다.
2. `test/ports/`의 공용 시험에 한 줄을 추가해 통과시킨다. 예:
   `historyRepositoryContract('SQLite', () => SqliteHistoryRepository.inMemory())`
3. `bootstrap.dart`의 내 줄만 바꾼다.
4. `flutter analyze` 0건, `flutter test` 통과.
5. 에뮬레이터에서 직접 확인하고 결과를 `ai_log`에 적는다.
6. 다른 한 명의 리뷰를 받고 합친다.

| 구현 | 자동 시험 | 에뮬레이터에서 직접 확인할 것 |
|---|---|---|
| `AssetGuidanceRepository` | 맵 공용 시험 + 위 5-3 | 맵을 바꿔 앱에서 안내가 달라지는지 |
| `PickerCameraInput` | 결과 모양 시험(`cameraInputContract`) | 촬영, 카메라 닫기, 권한 거부(두 번 거부 포함), 설정 열기 후 복귀 |
| `FileInputCleanup` | 포트 시험(`inputCleanupContract`) + 임시 폴더 생성·삭제 시험 | 홈으로 돌아간 뒤 `sg_` 폴더가 0개, 앱 재시작 후 남은 폴더 정리 |
| `MediaGalleryInput` | 결과 모양 시험(`galleryInputContract`) | 허용·거부, 목록 9장, 스크린샷 배지, 한 장 선택 후 분석까지 |
| `SqliteHistoryRepository` | 기록 공용 시험(`historyRepositoryContract`) | 저장 → 앱 종료 → 재시작 → 남아 있음, 삭제 |
| `SharePlusSharer` | 포트 시험(`sharerContract`) | 공유 시트가 열리고 텍스트만 들어 있음, 닫기·보내기 결과 |

입력 포트는 사용자 동작이 필요해 자동 시험이 결과의 **모양**만 확인한다(골격 주석). 에뮬레이터 확인은 실기기 확인이 아니므로 기록에 "에뮬레이터"라고 적는다. 실기기가 없으면 없다고 적는다.
