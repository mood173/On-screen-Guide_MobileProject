## 4. 작업 규칙

- 내 폴더: 각 기능의 `data/`(capture, guidance_map, history, share), `assets/feature_maps/`(스키마·형식), `.github/workflows/`. 남의 폴더는 요청으로만.
- `ui/`·`handlers/`·`app/`은 `data/`를 import하지 않는다. 구현 클래스를 만드는 곳은 `app/bootstrap.dart`뿐이고, 거기서는 **내 인터페이스 줄만** 바꾼다.
- 인터페이스 메서드는 예외를 던지지 않고 실패를 결과 값으로 돌려준다.
- 진짜 구현 → `test/ports/port_contracts.dart` 공용 시험 통과 → bootstrap 줄 교체 → `flutter analyze` 0건·`flutter test` 통과 → 에뮬레이터 확인 → 다른 1명 리뷰 → Merge.
- 원본 이미지·화면에서 읽은 글자·개인정보 후보 값은 기록·공유·로그에 넣지 않는다. 위치·연락처 권한을 요청하지 않는다.
- 계약 변경은 협업규격 3장을 먼저 고치고 팀에 알린 뒤 코드에 반영한다.
- 브랜치는 `feat/<주제>`. 프로젝트 경로에 한글·공백 금지(Gradle).

## 5. 인터페이스 요약 (협업규격 3장, 상세는 원문)

- `GalleryInput { requestAccess, recent({limit=9}), use(id) }`, `CameraInput { takePhoto }`, `InputCleanup { release, clearLeftovers, openAppSettings }` → `PickedImage{status,path,input}`, `PickStatus{ok,cancelled,permissionDenied,readFailed}`
- `GuidanceRepository { fragment, actionsFor(screenId), activeRevision }`, `MapUpdater { checkForUpdate }`
- `HistoryRepository { save, list, get, delete }`, `HistoryEntry`에 이미지 칸 없음
- `Sharer { shareText }` → `ShareOutcome{sent,dismissed,failed}`
- 기능 맵 규칙: 화면 ID `앱.화면`, 앵커 2개 이상·서로 포함 금지, 기능 ID `영역.동작`, 단계 1~5개, 선택자 2자 이상·OCR에서 한 줄로 읽히는 글자
- 저장 스키마(`FeatureMap`, `AppGuide` 등)는 `data/` 안쪽에서만 쓴다.
