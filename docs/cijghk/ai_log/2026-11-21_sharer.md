## 1. 맡긴 일

`Sharer`의 진짜 구현: 사용 방법 **텍스트만** Android 공유 시트로 보내고, 보냄·닫음·실패를 `ShareOutcome`으로 돌려준다. 이미지를 받는 메서드는 만들지 않는다. 닫음·실패가 예외로 번지지 않게 한다. bootstrap의 `sharer` 줄을 바꾼다.

결과 변환:

| share_plus | ShareOutcome |
|---|---|
| `success` (사용자가 앱을 고름) | `sent` |
| `dismissed` (시트를 닫음) | `dismissed` |
| `unavailable` (시트는 열렸지만 결과를 모름) | `sent` **[제안 — 팀 확인]** |
| 빈 텍스트, 예외 | `failed` |

## 3. 하나씩 물어본 것

| 물어본 것 | AI의 설명 |
|---|---|
| Android에서 결과를 얼마나 아나 | share_plus 문서·코드상 Android는 "앱을 골랐는지 / 시트를 닫았는지"까지만 기록한다. 고른 앱에서 실제로 보냈는지는 모른다 |
| `unavailable`을 왜 `sent`로 | 시트는 열려 사용자가 공유할 수 있었지만 결과를 모르는 경우다. `dismissed`로 두면 흐름이 "들어온 곳으로" 돌아가 실제로 보낸 사용자에게 어색하다. 설계 문서 9장 6번(지형주와 정할 일)으로 남긴다 |
| 빈 텍스트는 | share_plus가 `ArgumentError`를 던지므로 그 전에 `failed`로 돌려준다 |
| 계약의 어느 줄을 지키나 | 규격 3.1 "텍스트만, 이미지를 받는 메서드는 만들지 않는다", 3.2 `ShareOutcome` 세 값, 3장 공통규칙 1(예외 없음), 4.3 #7 |
| 공유 전 확인(P)은 | 흐름의 관문이 지킨다(규격 3.4). 이 구현은 받은 텍스트를 보내기만 한다. 텍스트에 인식 글자·가린 값이 섞이지 않는지는 공유 텍스트 함수(강민준/지형주)와 그 시험이 맡는다 |
| 권한이 더 필요한가 | 아니다. share_plus 매니페스트는 파일 공유용 provider만 선언하고 권한을 요구하지 않는다(텍스트만 쓰므로 provider도 쓰지 않음) |

## 4-1. 에뮬레이터 확인

| 확인 | 결과 |
|---|---|
| SHARE | 시스템 공유 시트(`com.android.intentresolver`)가 열림. "Sharing text" 미리보기에 `메시지 보내기 … / 1. 메시지 입력 칸을 눌러주세요 / 2. 보내기를 눌러주세요` 그대로 |
| 시트를 뒤로 가기로 닫음 | `SHARE → dismissed` (Claude가 adb로 확인) |
| 시트에서 앱을 고름 | 사용자가 "잘 된다"고 확인. 화면의 결과 글자(`sent`)는 기록하지 못했다 |
