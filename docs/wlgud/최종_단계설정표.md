# 최종 · 단계 설정표 (버튼 관문·화면 틀·단계 진입/이탈)

2026-11-14 · 지형주 · 브랜치 `feat/input-connect` (협업규격_최종 4.2 3번)
작업 기록: `ai_log/2026-11-14_단계설정표.md` · 설계: 시스템설계_최종 3장(단계 표)·4-1(셸)·6-2(흐름 구조)·6-4 3·6번

## 하는 일

앱의 화면 33개를 **단계 11개**(준비, 대기, 입력, 분석, 선택, 안내, 마무리, 공유, 복구, 기록·설정, 실시간)로 묶고, 단계마다
"누를 수 있는 버튼", "화면 틀(셸·진행 칸)", "들어갈 때·나갈 때 할 일"을 정한다. 화면은 그리기만 하고,
버튼이 켜질지는 `flow.allows(id)`가 이 표를 보고 정한다. 골격의 화면별 관문 표(`GuideFlow._gate`)를 대신한다.

```
버튼 → flow.dispatch(id)
        ├ 관문 allows(id)  = 단계 설정표(이 장면에서 원래 되는 버튼) − 지금 상태로 잠글 것
        ├ 처리 (switch)
        └ 화면 이동 _go(화면) → 단계가 바뀌면 _onExit(나가는 단계) → _onEnter(들어가는 단계)
```

## 쓰는 법

| 항목 | 내용 |
|---|---|
| 화면 → 단계 | `lib/app/stage.dart` — `enum Stage`, `ScreenId.stage` (extension, 공동 계약 `screen_id.dart`는 안 고침) |
| 표 | `lib/app/stage_table.dart` — `StageTable.ruleFor(stage)` → `StageRule { shell, progress, allowed, byScene }` |
| 버튼 관문 | `GuideFlow.allowed` / `allows(id)`. 화면은 `flow.allows(id) ? () => flow.dispatch(id) : null` |
| 진행 칸 | `GuideFlow.progress` (1 입력 ~ 5 완료, 없으면 null. 복구 화면은 실패한 단계의 칸) |
| 진입·이탈 | `GuideFlow._go` → `_onExit` / `_onEnter` |

**새 버튼을 열 때**: `stage_table.dart`의 해당 단계 `allowed`에 넣고, 그 장면만 좁혀야 하면 `byScene`에도 넣는다
(장면 목록은 단계 기본의 일부여야 한다 — 시험이 확인). 그다음 `GuideFlow.dispatch`의 switch에 처리를 추가한다.
**새 단계·새 화면 ID가 생기면**: `stage.dart`·`ruleFor`·`_onEnter`·`_onExit`의 switch가 컴파일 오류로 빠진 곳을 알려 준다.
