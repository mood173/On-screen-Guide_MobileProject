## 3. 하나씩 물어본 것

| 단위 | 물어본 것 | AI의 설명 | 내 판단 |
|---|---|---|---|
| 5-1 | 5번 자체가 버튼 일인가 | 아니다. 5번은 안내가 끝난 뒤 쓰는 화면 셋(기록·설정·공유)이다. 등록부는 그 버튼들이 "누르면 무엇을 하나"를 빠짐없이 적는 바탕이라 먼저 한다 | |
| 5-1 | 관문과 등록부는 무엇이 다른가 | 관문(`allows`, 단계 설정표) = 지금 눌러도 되나. 등록부(`dispatch`의 switch) = 누르면 무엇을 하나 | |
| 5-1 | 왜 `default:`를 지우나 | `default`가 있으면 ID를 추가하고 처리를 잊어도 조용히 "준비 중"이 된다. 지우면 Dart가 빠진 갈래를 컴파일 오류로 알려 준다. 갈래 하나를 일부러 지워 `non_exhaustive_switch_statement` 오류가 나는 것을 확인했다 | |
| 5-1 | 왜 `ActionRegistry` 클래스를 안 만드나 | 11/14 결정 ①(switch 유지), 역할설계 U4가 구현을 "`switch` 문"으로 적음, 일정_현실검토 3-2가 같은 방식을 제안. 컴파일러가 "모든 ID에 핸들러"를 대신 확인한다. 시스템설계 6-2의 `ActionRegistry`와는 다르다 | |
| 5-1 | 시험은 무엇을 확인하나 | ① '준비 중' 목록이 정한 13개와 같다 (기능을 만들면 시험도 같이 고쳐야 해서 남은 일이 보인다) ② 28개 모두를 `handle`로 눌러, 목록에 있는 것만 "준비 중" 문구가 나온다 ③ 화면에서(관문을 거쳐) 준비 중 버튼을 누르면 화면은 그대로, 문구만 | |
| 5-1 | 왜 `handle`을 따로 열었나 (점검) | 관문이 막는 버튼은 `dispatch`로 누를 수 없어 홈에서 13개 중 3개만 확인됐다. `sharePrepare`에 진짜 처리를 넣고 목록에서 안 빼도 시험이 통과하는 것을 실험으로 확인 → 관문 없이 처리만 하는 `handle`을 시험 전용(`@visibleForTesting`)으로 열었다. 화면은 계속 `dispatch`만 부른다 | |
| 5-2 | 고른 것이 문서와 부딪히나 | 공동 계약(버튼 ID·화면 ID·포트)과는 없음. ① 목록을 흐름이 가짐 = 협업규격 3.6·4-2 규칙 1 ② 다시 보기를 HISTORY 안에서 = 9장 "historyOpen → 기록, get, 세션 변화 —" ③ 확인창은 화면 = 4-2 규칙 3 ④ 하단 탭 = 4-1·3-9 ⑤ 홈 최근 기록 3건(3-2)은 미룸. Figma와는 3곳이 다름(아래 5-2 결정) | |
| 5-2 | 추천이 거의 문서대로인가 | 기준이 "기능은 문서, 모양은 Figma"(11/11 기준 5개, DENY 때도 같음). 다른 3곳이 모두 기능(어디로 가나·지우기가 있나·무엇을 보이나)이라 문서. 보이는 것은 대부분 Figma | |
| 5-2a | 펼친 기록은 왜 세션 값이 아닌가 | 9장이 "세션 변화 —"로 적음. 안내 세션(입력·분석·기능)과 상관없는 기록 화면 값이라, 기록 단계를 떠날 때 비운다 | |
| 5-2a | 이미 지워진 기록을 열면 | `get`이 null → 펼치지 않고 목록을 새로 읽는다 (예외 없이) | |
| 5-2a | 시험이 잡는지 | 핵심 줄 두 개(펼친 것을 지우면 닫기, 떠날 때 비우기)를 하나씩 지워 보니 각각 시험이 실패 | |
| 5-2b | Figma가 바뀌면 문제없나 | 색·크기는 토큰, 배치·문구는 화면 파일 하나만 고친다. 흐름과 흐름 시험은 그대로. 버튼·화면이 늘면 기능 변경이라 문서·팀 확인부터. 위젯 시험은 장식 문구(제목·부제)를 찾지 않고 문서가 뜻을 정한 글자만 본다 | |
| 5-2b | 문서와 부딪히나 (만들기 전 점검) | 계약과는 없음. 다만 하단 탭이 흐름을 받으면 팀 의존 규칙("shared/는 app/을 보지 않는다", dependency_rules_test 105줄)에 걸림 → 탭별 동작(`VoidCallback?`)만 받게 함. `GuideScaffold.onBack`과 같은 방식. 셀 표(4-2) "기록 줄"은 `historyOpen`만 적었지만 3-9가 `historyDelete`도 허용 → 셀 표가 덜 적힌 것으로 봄 | |
| 5-2b | 관문 확인 함수 `_on`이 홈·기록에 두 번 있는 이유 | 공용으로 빼려면 `app/`에 둬야 하는데 기록 화면은 `app/guide_flow.dart`만 볼 수 있다. 두 줄이라 중복을 받아들임. 설정(5-3)까지 셋이 되면 다시 본다 | |
