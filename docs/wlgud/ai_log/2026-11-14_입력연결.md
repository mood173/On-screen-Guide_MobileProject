## 3. 하나씩 물어본 것

| 단위 | 물어본 것 | AI의 설명 | 내 판단 |
|---|---|---|---|
| A | 왜 결과 처리를 함수 하나로 모으나 | 3.4 표는 갤러리·카메라 공통이다. 지금은 갤러리 두 곳(권한 확인, 사진 사용)에 따로 있고 카메라(B)가 붙으면 세 곳이 된다. 한 함수에 표를 그대로 옮기면 표와 코드를 한 줄씩 맞춰 볼 수 있다 | |
| A | 권한 거부는 왜 E가 아니라 DENY인가 | 3.4 표가 DENY로 정했다. DENY는 "설정 열기 + 다른 방법으로 대신하기"(3-9)라 오류 화면의 "다시 고르기"와 할 일이 다르다. 권한이 없으면 다시 골라도 또 거부된다 | |
| A | 거부된 입력 방식은 왜 기록하나 | DENY 화면이 대신할 방법을 고르려면 무엇이 거부됐는지 알아야 한다 (카메라 거부 → "갤러리로 대신하기", 갤러리 거부 → 설정 열기만). 화면 C에서 쓴다 | |
| A | "ok인데 경로 없음"은 왜 읽기 실패인가 | 분석에 넘길 파일이 없으니 쓸 수 없는 이미지다. 골격 코드도 같은 경우를 읽기 실패로 처리했다 (`PickedImage.ok` = 상태 ok + 경로 있음) | |
| A | `switch`에 `default`가 없는데 `PickStatus.ok`는 왜 있나 | `default`를 두지 않아 상태가 새로 생기면 컴파일 오류가 나게 했다. 그래서 ok도 갈래가 있어야 하고, 이 함수에 ok로 들어오는 경우는 위의 "경로 없음"뿐이다 | |
| A | 시험이 확인하는 것 / 안 하는 것 | 확인: 사진 사용에서 취소 → GS 유지, 거부 → DENY·denied·기록=갤러리, 읽기 실패 → E, 홈으로 가면 기록 지움, 권한 확인 거부 → DENY. 안 함: 카메라(B), DENY 화면의 버튼(C) | |
