## 3. 하나씩 물어본 것

| 단위 | 물어본 것 | AI의 설명 | 내 판단 |
|---|---|---|---|
| A | 왜 결과 처리를 함수 하나로 모으나 | 3.4 표는 갤러리·카메라 공통이다. 지금은 갤러리 두 곳(권한 확인, 사진 사용)에 따로 있고 카메라(B)가 붙으면 세 곳이 된다. 한 함수에 표를 그대로 옮기면 표와 코드를 한 줄씩 맞춰 볼 수 있다 | |
| A | 권한 거부는 왜 E가 아니라 DENY인가 | 3.4 표가 DENY로 정했다. DENY는 "설정 열기 + 다른 방법으로 대신하기"(3-9)라 오류 화면의 "다시 고르기"와 할 일이 다르다. 권한이 없으면 다시 골라도 또 거부된다 | |
| A | 거부된 입력 방식은 왜 기록하나 | DENY 화면이 대신할 방법을 고르려면 무엇이 거부됐는지 알아야 한다 (카메라 거부 → "갤러리로 대신하기", 갤러리 거부 → 설정 열기만). 화면 C에서 쓴다 | |
| A | "ok인데 경로 없음"은 왜 읽기 실패인가 | 분석에 넘길 파일이 없으니 쓸 수 없는 이미지다. 골격 코드도 같은 경우를 읽기 실패로 처리했다 (`PickedImage.ok` = 상태 ok + 경로 있음) | |
| A | `switch`에 `default`가 없는데 `PickStatus.ok`는 왜 있나 | `default`를 두지 않아 상태가 새로 생기면 컴파일 오류가 나게 했다. 그래서 ok도 갈래가 있어야 하고, 이 함수에 ok로 들어오는 경우는 위의 "경로 없음"뿐이다 | |
| A | 시험이 확인하는 것 / 안 하는 것 | 확인: 사진 사용에서 취소 → GS 유지, 거부 → DENY·denied·기록=갤러리, 읽기 실패 → E, 홈으로 가면 기록 지움, 권한 확인 거부 → DENY. 안 함: 카메라(B), DENY 화면의 버튼(C) | |
| B | B는 설계 문서와 관계있나 | 대부분 문서 그대로: 화면 CP·CR·CA·RC(3-0), CP부터·`takePhoto`·결과 전이(3-3, 협업규격 3.1·3.4), 기본 카메라(13장 X2), 위젯 하나(3-0), 세션이 입력 방식 기억(3-3·3-6·협업규격 3.6), 다시 고를 때 삭제(3.4 호출 시점). 선택한 것: 다시 찍을 때 CP 건너뛰기, B에서 화면 연결, `_scene` 이름 | 추천대로 결정 (11/14) |
| B | 왜 다시 찍을 때 앞 사진을 **나중에** 지우나 | 갤러리 `_confirm`은 먼저 지우지만, 카메라 다시 찍기는 CR·RC 화면 위에서 일어난다. 먼저 지웠다가 사용자가 카메라를 닫으면(취소) 지금 화면이 그릴 사진이 없어진다. 새 사진을 받은 뒤 지우면 취소해도 앞 사진이 그대로 | |
| B | `_scene(...)` 없이 다섯 곳에 `if (input == camera)`를 쓰면 | 같은 조건이 다섯 번 반복되고, 하나만 빠뜨려도 카메라 세션이 갤러리 화면으로 튄다. 함수 하나면 "갤러리면 이것, 카메라면 저것"을 한 줄로 읽을 수 있다 | |
| B | 단계 설정표(관문)는 왜 안 고쳤나 | CP·CR·E에서 `captureCamera`, CR에서 `analyzeRun`·`captureRetake`가 이미 허용돼 있다 (단위 2). 표를 먼저 만든 덕분 | |
| B | 시험이 확인하는 것 / 안 하는 것 | 확인: H→CP→CR→RC, 촬영 취소·거부(DENY, 기록=카메라)·읽기 실패, 분석 취소→CR, RC·CR에서 뒤로, CR 다시 찍기(CP 안 거침, 앞 사진 삭제), 다시 찍기 취소(앞 사진 남음). 안 함: CP 화면 모양(C), 진짜 카메라(PR #3 머지 뒤 기기 확인) | |
| B | 연타 잠금은 왜 "모든 버튼"인가 (단위 3의 찾는 중 잠금은 단계 버튼 셋만) | 가져오는 사이 뒤로를 누르면 홈으로 갔다가 늦게 온 사진이 GR·CR을 띄운다. 카메라가 열려 있는 동안은 어차피 앱 화면이 가려져 있고 갤러리 복사는 짧아서, 전부 잠가도 불편이 거의 없다. 규칙이 "가져오는 중엔 아무것도 안 됨" 한 줄이라 설명도 쉽다 | |
| B | 왜 try/finally인가 (포트는 예외를 안 던진다는 규칙이 있는데) | 성공·실패·취소 세 길이 있고 실패는 중간에 `return`한다. 끄는 줄을 길마다 쓰면 하나를 빠뜨리기 쉽다. finally는 어느 길로 나가도 한 번 실행된다 | |
