## 3. 하나씩 물어본 것

| 물어본 것 | AI의 설명 | 내 판단 |
|---|---|---|
| 왜 `ScreenId` 파일을 고치지 않고 `extension`으로 `stage`를 붙이나 | `shared/contracts/`는 공동 폴더라 바꾸려면 세 명 확인이 필요(협업규격 2장). `lib/app/`은 팀원 2 지형주 (화면·흐름) 폴더. extension을 쓰면 문서의 `ScreenId.stage` 모양(`screen.stage`)은 그대로 쓰면서 공동 파일은 건드리지 않는다 | |
| 관문을 단계 단위로만 두면 안 되나 | 시스템설계 3-3은 입력 단계 전체의 버튼을 한 줄로 적었지만, 지금 코드는 G에서 `capturePick`만 허용한다. 단계 단위로 넓히면 기존 시험의 의미가 바뀐다. 3-8·3-9는 문서도 장면(P/SHARE, DENY/E)별로 적었으므로 "단계 기본 + 장면별 좁히기"가 문서와 맞다 | |
| 실시간 안내(LP~LG5) 화면은 어느 단계인가 | 3장 표에 없다(N01은 일정 제외). `Stage.overlay`를 따로 두고 허용 버튼은 비워 둔다. 나중에 N01을 하면 그 줄만 채우거나 단계를 나누면 되고, switch에 default가 없어 빠진 화면은 컴파일 오류로 잡힌다 | `Stage.overlay`로 결정 (11/14) |
| `switch`에 왜 `default`가 없나 | 화면 ID가 새로 생기면 단계 연결을 빠뜨린 곳에서 컴파일 오류가 나게 하려고. default가 있으면 조용히 엉뚱한 단계로 간다 | |
